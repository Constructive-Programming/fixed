# Runtime baseline, 2026-11-20

M10 (3.4.M6): demands, shared versions and memory facts consumed by the backend. Demand-0 parameters erased; `read` parameters borrowed where a caller keeps the argument; cells reused unconditionally where exclusively owned and after `rc == 1` otherwise (hybrid, drop-guided tokens). Comparison with the 4.0 baseline below.

- Commit: `ae2e398` (with local changes)
- Machine: Linux 7.2.15-gentoo-x86_64 x86_64, AMD RYZEN AI MAX+ 395 w/ Radeon 8060S
- Toolchain: clang version 22.1.8, `clang -O2`
- Wall time: best of 7 runs, measured by the runtime from `main` start to end (no process start-up).
- Counts are deterministic: every run gives the same allocations, reuses, `dup`s and `drop`s.

## Against the 4.0 baseline (`runtime-2026-11-19.md`, commit `5a824c1`)

Wall time is noisy on this machine (±5% between identical runs), so both builds were rebuilt and run
interleaved in the same session: best of 15, 4.0 binary then M10 binary, alternating.

| Program | Wall 4.0 (ms) | Wall M10 (ms) | Change | Allocations | dups | drops |
|---|---:|---:|---:|---|---|---|
| `bintrees` | 57.1 | 56.2 | −1% | unchanged | unchanged | unchanged |
| `nat_loop` | 63.6 | 66.6 | +5% (noise range) | unchanged | unchanged | unchanged |
| `list_pipeline` | 144.9 | 100.0 | **−31%** | 8.0 M → 4.0 M (4.0 M reuses) | unchanged | 22.0 M → 18.0 M |
| `records` | 80.4 | 65.6 | **−18%** | 5.0 M → 3.0 M (2.0 M reuses) | unchanged | 15.0 M → 13.0 M |
| `fail_chain` | 91.1 | 81.2 | −11% | unchanged | unchanged | unchanged |

- **Reuse is where the change comes from.** In `list_pipeline` every `map` cell is reused, exclusive
  versions without a test. In `records`, `map` reuses its cells and `discount` reuses each `Order`.
  The `fail_chain` difference has identical counts and is not attributable to M10 with confidence.
- **`dup`s did not move.** They come from field reads (a read field is dup'ed, then the parent's
  drop or token releases it) and from closures passed to recursive loops. Removing them needs
  drop specialisation (moving fields out of an exclusive cell instead of dup + release) and a
  borrowing closure-call convention: Phase 4 Perceus work, now with the facts to drive it.
- **Borrowing pays only where a caller keeps the argument.** Borrowing every `read` parameter made
  `bintrees` 18% slower: the fold no longer freed nodes as it read them, and the caller freed the
  whole tree in a second pass. Borrowing is now limited to parameters some caller keeps live after
  the call; none of the benchmarks has one.
- **Static and dynamic reuse both fire (hybrid).** `list_pipeline`'s `map` cells are reused
  statically (`fx_reuse_excl`, exclusive version). In `records`, the `Order` cells are reused on
  the dynamic path: `map` hands each element to a closure it cannot see, so the closure's shared
  entry calls `discount#1`, the shared version, which reuses after `rc == 1` (Koka's technique,
  Rule PR6.3). The derived `unfold`'s layer cell is not yet a reuse candidate, because lowering
  does not record its type.
